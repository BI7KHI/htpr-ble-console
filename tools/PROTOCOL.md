## 1. 传输层

Nordic UART Service (NUS) 透传：

| 用途 | UUID | 属性 |
|---|---|---|
| 服务 | `6e400001-b5a3-f393-e0a9-e50e24dcca9e` | — |
| 手机 → 设备 | `6e400002-b5a3-f393-e0a9-e50e24dcca9e` | `writeNoResponse` |
| 设备 → 手机 | `6e400003-b5a3-f393-e0a9-e50e24dcca9e` | `notify` |

**限制：模块同一时刻只允许 1 个中心设备连接**（连上后停止广播）。

## 2. 帧格式

固定 **67 字节**，约 **2 Hz**，两种帧交替下发：

| 字节 | 说明 |
|---|---|
| `[0][1]` | 帧头：`CA AC`(遥测帧) / `C9 9C`(仪表帧) |
| `[2][3]` | 命令字 BE：`96 05`(遥测) / `94 05`(仪表) |
| `[4..64]` | 数据区（**密文**，需解密） |
| `[65]` | 校验 = `sum(bytes[0..64]) & 0xFF` |
| `[66]` | 帧尾，恒为 `0xCC` |

> 另外还存在 `0x9405/0x9305`(参数帧)、`0x9A0A`(车辆状态帧)、三轮帧等，本控制器主要使用上表两种。

---

## 3. 加解密（关键！）

**所有以 `c99c` / `caac` 开头的帧，`[4..65]` 都经过滚动混淆**（小程序 `ab2hex` 中对这类帧统一调用 `decrypt()`）。

```
解密 (字节下标 o = 4..65):
    b = (b - 54) & 0xFF
    b ^= 43
    b = (b - o)  & 0xFF
    b ^= 101
    b = (b - o)  & 0xFF

加密 (下发命令时，逆运算):
    b = (b + o)  & 0xFF
    b ^= 101
    b = (b + o)  & 0xFF
    b ^= 43
    b = (b + 54) & 0xFF
```

字节 `0..3` 与 `66` 不参与变换。解密后校验必须通过。

## 5. 下发命令

命令帧同样以 `c99c` 开头，**构造流程**：

```
1) 明文帧   = 命令字(c99c0002 / c99c0602 / …) + 参数区
2) 清零无关位（ClearInterference）:
       hex[8..10]   = "00"
       hex[74..78]  = "0000"
       hex[120..130]= "0000000000"
3) byte[65] = sum(bytes[0..64]) & 0xFF
4) byte[66] = 0xCC
5) 整帧经 encrypt() 加密后 writeNoResponse 发出
```

小程序中共 25 处 `writeBLECharacteristicValue`，主要用于：写入功能设置、参数读写、OTA、液晶仪表选择等。

## 6. 参考实现

见同目录 `htpr_protocol.py`（纯 Python，无第三方依赖）：

```python
from htpr_protocol import parse_dashboard, parse_realtime, decrypt, encrypt, NUS_TX_CHAR, NUS_RX_CHAR

# 收到 BLE notify 的 67 字节 payload 后：
if payload[0] == 0xCA:          # 遥测帧
    r = parse_realtime(payload)
    print(r.ampere, 'A', r.rpm(), 'rpm')       # 电流 / 转速
else:                            # 仪表帧
    d = parse_dashboard(payload)
    print(d.voltage, 'V', d.throttle_voltage, 'V')   # 电压 / 转把电压
```

对接到手机端（Android/iOS/小程序）时，只需把 `decrypt()` 与两个 `parse_*()` 按同样逻辑移植即可。
